# Dual Boot with Windows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved design in `docs/superpowers/specs/2026-10-17-dual-boot-design.md`: when Windows (UEFI) is on another disk of the target, the Gentoo install keeps it bootable through an explicit GRUB menu entry frozen in the plan; Secure Boot is detected and refused for UEFI installs; a disk that holds Windows is never inferred and can only be erased with an extended typed confirmation.

**Architecture:** Two new read-only inventory commands (`partitions`, `secure_boot`) in `core/ssh.py`; a new pure module `core/foreign_os.py` that turns them into Windows records, the Secure Boot state, and the derived `dual_boot_entries`; the single validation gate (`core/validate.py`) checks every entry before it reaches a program; `core/phases.py` writes `/etc/grub.d/45_gentoo_agent_dualboot` and checks `grub.cfg`; `core/install_plan.py` freezes the entries, the Windows disk identities, the Secure Boot state, warnings, and `erases_existing_os` into the hashed plan; `core/approval.py` and the three front ends (CLI `approve`, MCP `approve_plan`, `prepare_install.py`) require `ERASE WINDOWS <disk>` when the install disk holds Windows. Only Task 4 changes generated commands: it adds a seventh golden configuration and leaves the existing six golden files byte-identical.

**Tech Stack:** Python 3.12+ standard library (`unittest`, `json`, `re`, `shlex`), optional `mcp==2.2.0` for the MCP tests (run them with `.venv/bin/python`).

**Task order:** the suggested order put the bootloader phase after plan creation and approval. This plan moves it to Task 4, directly after the setting and its validation (Task 3), because the generators only need a validated `dual_boot_entries`, and because plan creation (Task 5) must never freeze a plan whose entries the bootloader program silently ignores. Every commit therefore produces plans whose commands match their entries.

### Task 2: Detect Windows and Secure Boot from the inventory

**Files:**
- Create: `gentoo_agent/core/foreign_os.py`, `tests/test_foreign_os.py`
- Modify: `gentoo_agent/core/validate.py` (two constants), `gentoo_agent/core/hardware.py` (`summarize_inventory`), `tests/helpers.py` (partition fixtures)
- Test: `tests/test_foreign_os.py`, `tests/test_hardware.py`

Design decisions taken here (the spec leaves them open):
- The `partitions` command has no `PTTYPE` column, so "MBR disk" means a partition whose `parttype` is an MBR type byte (`0x7`, matched by `0x[0-9a-f]{1,2}`); an MBR EFI system partition is `0xef`.
- A missing or failed `partitions` result raises `INVENTORY_MISSING`. Plan creation and `resolve_config` fail closed on it (Tasks 3 and 5), because without it the Windows erase confirmation could be skipped.
- Discovery never raises on it: `summarize_inventory` reports `existing_os: "unknown"` for every disk when the partition list is missing or unusable (in addition to the spec's `windows`, `windows-bios`, and `null`), matching how it already reports `boot_mode` and `architecture`.
- Values are checked only where they are used: every disk and partition path must pass `DEVICE_PATH`; the ESP UUID and PARTUUID of a Windows record must pass `ESP_UUID` and `PARTUUID`; type GUIDs and filesystem names are only compared with constants and never copied.
- `foreign_os.py` reuses the lsblk JSON parser `disks._block_devices` (same package, same `INVENTORY_MISSING` behavior) instead of a second copy.

```python
"""Other operating systems on the target's disks, and the Secure Boot state.

Pure: reads a saved inventory and never contacts the target. Every value in
the inventory is untrusted. A value that does not match its strict format
makes the inventory unusable (INVENTORY_MISSING, refresh it); it never reaches
a generated program or the approval dialog.
"""

from __future__ import annotations

import re

from gentoo_agent.core.disks import _block_devices, inventory_results
from gentoo_agent.core.errors import INVENTORY_MISSING, AgentError
from gentoo_agent.core.validate import DEVICE_PATH, ESP_UUID


PARTITIONS_LABEL = "partitions"
SECURE_BOOT_LABEL = "secure_boot"
ESP_TYPE = "c12a7328-f81f-11d2-ba4b-00a0c93ec93b"
MSR_TYPE = "e3c9e316-0b5c-4db8-817d-f92df00215ae"
BASIC_DATA_TYPE = "ebd0a0a2-b9e5-4433-87c0-68b6b72699c7"
# MBR partition types are printed as hex bytes (0x7 for NTFS, 0xef for an EFI system partition).
MBR_TYPE = re.compile(r"0x[0-9a-f]{1,2}")
MBR_ESP_TYPE = "0xef"
PARTUUID = re.compile(r"[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}")
SECURE_BOOT_STATES = {"1": "on", "0": "off"}


def _unusable(message: str) -> AgentError:
    return AgentError(INVENTORY_MISSING, f"{message}; refresh the inventory.", {"label": PARTITIONS_LABEL})


def _text(device: dict, key: str) -> str:
    value = device.get(key)
    if value is None:
        return ""
    if not isinstance(value, str):
        raise _unusable(f"The partitions inventory has a non-text {key}")
    return value


def _path(device: dict) -> str:
    path = _text(device, "path")
    if not DEVICE_PATH.fullmatch(path):
        raise _unusable("The partitions inventory lists an unsafe device path")
    return path


def _partitions(disk: dict) -> list[dict]:
    children = disk.get("children")
    if children is None:
        return []
    if not isinstance(children, list) or not all(isinstance(child, dict) for child in children):
        raise _unusable("The partitions inventory is malformed")
    return [child for child in children if _text(child, "type") == "part"]


def _checked(record: dict) -> dict:
    if not all(isinstance(item, str) and item.isprintable() for item in record["evidence"]):
        raise _unusable("The partitions inventory has unprintable evidence")
    return record


def _windows_record(disk_path: str, partitions: list[dict]) -> dict | None:
    esp: dict | None = None
    esp_path = ""
    windows: list[str] = []
    bios_ntfs: list[str] = []
    any_esp = False
    for part in partitions:
        path = _path(part)
        parttype = _text(part, "parttype").lower()
        fstype = _text(part, "fstype").lower()
        if parttype in (ESP_TYPE, MBR_ESP_TYPE):
            any_esp = True
        if parttype == ESP_TYPE and fstype == "vfat" and esp is None:
            esp, esp_path = part, path
        elif parttype == MSR_TYPE:
            windows.append(f"msr {path}")
        elif parttype == BASIC_DATA_TYPE and fstype == "ntfs":
            windows.append(f"ntfs {path}")
        elif MBR_TYPE.fullmatch(parttype) and fstype == "ntfs":
            bios_ntfs.append(f"ntfs {path}")
    if esp is not None and windows:
        esp_uuid = _text(esp, "uuid")
        esp_partuuid = _text(esp, "partuuid").lower()
        if not ESP_UUID.fullmatch(esp_uuid):
            raise _unusable(f"The EFI system partition {esp_path} has an unexpected UUID")
        if not PARTUUID.fullmatch(esp_partuuid):
            raise _unusable(f"The EFI system partition {esp_path} has an unexpected PARTUUID")
        return _checked({"disk": disk_path, "os": "windows", "esp_uuid": esp_uuid, "esp_partuuid": esp_partuuid,
                         "evidence": [f"esp vfat {esp_path}", *windows]})
    if bios_ntfs and not any_esp:
        return _checked({"disk": disk_path, "os": "windows-bios", "evidence": bios_ntfs})
    return None


def detect_foreign_os(inventory: dict) -> list[dict]:
    """One record per disk that holds Windows: UEFI ("windows") or BIOS ("windows-bios")."""
    item = inventory_results(inventory).get(PARTITIONS_LABEL)
    if item is None or item.get("returncode") != 0:
        raise AgentError(INVENTORY_MISSING, "The latest inventory has no partition list; refresh it.",
                         {"label": PARTITIONS_LABEL})
    records = []
    for disk in _block_devices(item.get("stdout"), PARTITIONS_LABEL):
        if _text(disk, "type") != "disk":
            continue
        record = _windows_record(_path(disk), _partitions(disk))
        if record is not None:
            records.append(record)
    return records


def parse_secure_boot(inventory: dict) -> str:
    """'on', 'off', or 'unknown' (missing probe, failed probe, or anything other than 1 or 0)."""
    item = inventory_results(inventory).get(SECURE_BOOT_LABEL) or {}
    stdout = item.get("stdout") if item.get("returncode") == 0 else None
    return SECURE_BOOT_STATES.get(stdout.strip(), "unknown") if isinstance(stdout, str) else "unknown"
```

- With exactly one eligible disk that holds Windows (UEFI or BIOS), `resolve_config` raises `DISK_AMBIGUOUS` with a message that the disk is never chosen automatically, and `details.existing_os`. def dual_boot_lines(entries: list[dict]) -> list[str]:
```python
    """Chroot lines that check each Windows ESP and write the GRUB script with one menu entry per Windows.

    Runs after grub-install and before grub-mkconfig. The script is rewritten on every run, so the
    phase stays idempotent; /etc/grub.d/40_custom is never touched. Empty entries add no lines.
    """
    if not entries:
        return []
    lines = []
    for entry in entries:
        uuid = entry["esp_uuid"]
        message = f"Windows EFI partition {uuid} not found; refresh the inventory"
        lines.append(f"if ! test -b \"$(blkid -U {q(uuid)} || true)\"; then printf '%s\\n' {q(message)} >&2; exit 1; fi")
    script = ["#!/bin/sh", 'exec tail -n +3 "$0"']
    for entry in entries:
        script += [
            f"menuentry 'Windows Boot Manager (on {entry['disk']})' --class windows {{",
            "    insmod part_gpt",
            "    insmod fat",
            f"    search --no-floppy --fs-uuid --set=root {entry['esp_uuid']}",
            f"    chainloader {entry['loader']}",
            "}",
        ]
    lines += [
        f"printf '%s\\n' {' '.join(q(line) for line in script)} > {q(DUAL_BOOT_SCRIPT)}",
        f"chmod 755 {q(DUAL_BOOT_SCRIPT)}",
    ]
    return lines


def dual_boot_checks(install: dict) -> list[str]:
    """One grep per Windows entry: a grub.cfg without it never counts as a complete bootloader."""
    grub_cfg = q(MOUNT_ROOT + "/boot/grub/grub.cfg")
    return [f"grep -Fq {q('search --no-floppy --fs-uuid --set=root ' + entry['esp_uuid'])} {grub_cfg}"
            for entry in validated_dual_boot_entries(install)]
```

```python
def _check_secure_boot(install: dict, secure_boot: str) -> list[str]:
    """Refuse a UEFI install while Secure Boot is on; warn when its state is unknown."""
    if install.get("boot_mode") != "uefi":
        return []
    if secure_boot == "on":
        raise AgentError(CONFIG_CONFLICT, "Secure Boot is on, and the installed GRUB is not signed. Turn Secure Boot "
                         "off in the firmware setup, boot the live ISO again, and refresh the inventory.",
                         {"secure_boot": "on"})
    if secure_boot == "unknown":
        return ["Secure Boot state is unknown; if it is on, the firmware will refuse to start GRUB. "
                "Check the firmware setup before approving."]
    return []


def _foreign_os_warnings(install: dict, records: list[dict]) -> list[str]:
    return [f"Windows in BIOS mode on {record['disk']} will not be in the GRUB menu."
            for record in records if record["os"] == "windows-bios" and record["disk"] != install["disk"]]
```

Design decisions:
- The approval record gains a required boolean `erase_confirmed`. Records written before this change lack it and therefore count as invalid (approvals expire after 60 minutes anyway); a non-boolean value is invalid.
- `require_approved_plan()` (through `_check`, which `approval_status()` shares) refuses a plan with `erases_existing_os` unless `erase_confirmed` is `true`, with `APPROVAL_REQUIRED` and the CLI command.
- In the MCP dialog the extra field is a required `StrictStr` named `confirm`. The MCP SDK raises `ValueError` when an accepted answer does not match the form (for example without `confirm`); `approve_plan` maps that to `APPROVAL_DECLINED`, as the spec requires for a missing value. Other elicitation failures keep failing closed with `APPROVAL_REQUIRED`. The existing non-boolean `approve` test only asserts an error, so it is unaffected.
- The dialog labels the extra disks of Task 5 as `Windows disk (kept, not written):` so a human never reads them as disks to erase. Plan warnings appear as `WARNING:` lines right after the destructive phases line.
